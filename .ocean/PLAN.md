# Ocean plan: Roster

**Spec:** `docs/DESIGN.md`. **Verify:** `bun test && bun run typecheck`.

## Guardrails (every worker and every sprint)
- **DEADLINE:** 2026-10-12T18:25Z (Mon 23:55 IST). FEATURE FREEZE: 2026-10-12T06:25Z (Mon 11:55 IST). No new sprint starts after the freeze; only fixes and evidence.
- **Product code** is written only by the four recorded setups through `scripts/run-setup.sh <setup> <Txx>`, which assigns setups from the seeded table in `experiments/PREREGISTRATION.md`.
  - The orchestrator reviews each task, runs verify, merges with `git merge --no-ff task/Txx` and never squashes.
  - Orchestrator-only commits carry the `ops:` prefix.
  - Up to 5 tasks run at once, one worktree each.
- **Commits:** commit as work lands. Never rewrite history or force-push.
- **Docs:** no internal strategy docs in this repo. No numbers except generated `docs/FACTS.md`. Never describe unbuilt work as done.
- **Operator-run only** (the only-stop list): credentials and logins, deploys and public posts, spending beyond the per-run budget caps, and pull requests to anyone else's repo.

### SP2 Recorded agent sessions working
- **Goal:** a headless setup session runs in a worktree, commits, and gets an Entire checkpoint with model and tokens.
- **Depends on:** the operator having installed and enabled Entire (`--checkpoint-backend branch`) and logged in to the Claude Code CLI. Optional: Codex.
- **Steps:**
  1. Probe each setup's model id with one call, and record the resolved ids in `setups/*.json`.
  2. Run a 1-line canary task under A to confirm the checkpoint lands on `entire/checkpoints/v1`.
  3. Record the setup C decision (Codex, or the Haiku fallback) as an amendment to the pre-registration.
- **Acceptance:** `git log entire/checkpoints/v1` shows the canary's checkpoint, and its session metadata has `agent`, `model` and `token_usage`.
